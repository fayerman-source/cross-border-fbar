Flag definitions live in `src/cross_border_fbar/reconcile/flags.py`. The catalog supplies severity, the triggering condition, preparer actions, worksheet titles and client labels. Unknown codes fail at construction; the catalog test checks emitted codes in both directions.

Currency conflicts withhold the native maximum, dollar maximum and year-end balance. The preparer may correct the currency label for all statements only by choosing an observed currency and recording the supporting source note. This correction does not convert genuinely mixed currencies into one denomination: those documents need correction before calculating a single account value. The selection and note are audited and included in the signed worksheet.

When Treasury has no rate, the acknowledgement dialog accepts foreign currency units per USD, a verifiable source and a rate date. The date must be the last day of the tax year. Leaving the rate blank leaves the dollar amount undetermined. Recorded rates recompute the worksheet, appear next to the account and are included in its fingerprint. Reopening that review item removes its rate. Changing account figures requires acknowledgement of that account's flags again.

A misread amount, printed balance, opening balance or closing balance is corrected from the source viewer, with a required note. The model's reading is never overwritten: the correction sits beside it, the worksheet shows the figure as "corrected by reviewer" with what was read, and the audit trail records who, the original, the corrected value and the note. Input follows the printed-amount rules, except that text which doesn't read one clear way is refused rather than guessed at. Corrections apply before reconciliation, so maxima, flags, Form 8938 bounds and totals all recompute from them. A correction is part of the signed worksheet, and it voids acknowledgements on its own account only. If the readings later change so the page no longer reads as the correction recorded, the correction stops applying, stays on record and is noted in the audit trail.

The Korean gettext catalog is `src/cross_border_fbar/app/translations/ko.po`. Each stable message context names a label, with a translator comment identifying its grammar. English changes retain the old translation as fuzzy. A translation is reviewed only when `Last-Translator` names the human reviewer, the file header is not fuzzy and the matching entry is not fuzzy. Current fuzzy drafts can be used only with the preparer's explicit confirmation at approval. Stale English is never used as a reviewed translation.

The client note is assembled from the signed figures by one routine, once with the English phrases and once with their Korean, so the two versions match line for line. The preparer sees them side by side and chooses what the client gets: Korean, English or both. The choice and the exact text are recorded with the approval, and both versions are in the draft and the export. English needs no translation or review, so it can be released even if the Korean is held back; Korean or both still require confirming any unreviewed phrase.

Give `docs/korean-review.txt` to the native reviewer. It contains numbered English | Korean pairs and review status.
